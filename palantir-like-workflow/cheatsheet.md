# 工程要点速查卡：如何复制 Palantir 的"AI 原生 Ontology 构建"策略

> 面向工程实现者的浓缩版。读完本卡即可动手设计自己的 Palantir-like 流水线。

## 一、架构核心：三层咬合

```
┌─────────────────────────────────────────────────────────┐
│  AI 层：LLM + Agent + Evals + 人机协同（可换模型）          │
│  推理/编排/评估 —— 只管"想"                               │
├─────────────────────────────────────────────────────────┤
│  Ontology 层：对象/属性/链接 + 动作/函数（确定性、可治理）   │
│  语义接地 + 工具暴露 —— 只管"算"和"准"                     │
├─────────────────────────────────────────────────────────┤
│  数据层：联邦直连（不复制），任意来源                       │
└─────────────────────────────────────────────────────────┘
```

**不可妥协的原则**（Palantir 反复强调）：
1. 业务逻辑必须作为"确定性工具"暴露给 LLM，**不进 prompt**（控 token、防泄漏、可审计）
2. 权限在 agent 读/推理/执行**之前**强制，随业务对象走，不埋在聊天记录里
3. 模型可替换：上下文与逻辑与模型解耦，换模型前后必须做质量评测

## 二、自动构建流水线的四个动作（对应 Palantir 五层中的工程核心）

| 步骤 | 做什么 | Palantir 对应物 | 工程启示 |
|---|---|---|---|
| 1. 联邦接入 | 数据源直连，不复制 | Ontology Hydration | 先解决"不复制数据"的权限/联邦查询，别先建数仓 |
| 2. 模式推断 | 从数据自动推断 schema/类型 | Infer schema + 列→属性映射 | schema 推断是自动化的入口，必做 |
| 3. AI 生成转换 | 自然语言 → 可审计的转换逻辑 | Pipeline Builder Generate | 生成结果要像手写节点一样进版本管理，可解释 |
| 4. 实体消解 | AI 链接跨源重复实体 | Entity Resolution | 数据最脏的环节交给模型，但保留人工确认 |

## 三、私域模型部署的最小闭环（Self-host 文档原样）

1. 容器镜像跑推理服务器（**vLLM 或 Ollama**），暴露标准 OpenAI 兼容 API
2. 镜像发布到内部 Artifact 仓库
3. compute module 部署，min replicas ≥ 1
4. 注册模型，配置能力（capabilities）
5. 任意应用可选此模型，与商用模型并列

动机（官方原文）：数据主权（推理流量不出内网）、**air-gapped 部署**（零外联）、自有 GPU 控成本、抢先用新开源模型。

## 四、交付节奏：Bootcamp 模式

- 目标：**真实客户数据 + 几天内出可运行工作流**（官方原话 "zero to use case in days"）
- 实现：向导（选源→自动映射→自动生成动作）+ LLM 生成（转换/清洗）+ 评估（evals）+ 人机校验
- 人力重心从"建模"移到"校验与治理"——这是组织层的最大变化

## 五、最容易做错的三个点

1. **把 LLM 当唯一入口**：Palantir 的成功是"LLM 生成 + 确定性层执行"，不是裸 LLM 套壳
2. **忽略动作层审计**：模型出的是提案，写回系统必须过权限+审计+人工 checkpoint
3. **模型锁死**：必须在架构上保证换模型（含换成私有/开源/本地）无痛——这是主权 AI 叙事的根基

## 六、术语对照表

| Palantir 术语 | 含义 |
|---|---|
| Ontology | 企业数字孪生（语义 + 动能） |
| OAG | Ontology-Grounded Generation，用语义模型接地替代朴素 RAG |
| Ontology Hydration | 数据/模型灌注进 Ontology 的机制 |
| AIP Logic | 无代码 LLM 函数环境 |
| AIP Evals | AI 工作流评估框架 |
| Compute Module | Palantir 的计算容器运行时（自托管模型的宿主） |
| Apollo | 云无关持续交付层（任意环境部署的保障） |
