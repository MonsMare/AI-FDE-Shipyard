# AI-FDE 最小验证实验结论报告

- 日期：2026-08-08
- 实验：`palantir-aip-workflow/experiment/ai-fde-pilot/`（规范 README.md / 数据集 data/ + ground-truth.json / 交付 project/ + delivery-report.md / 评估 eval.js / 生成 gen.js）
- 上游结论：`docs/2026-08-08-paip-production-deep-analysis.md` 方向 C——让 AI 扮演 Palantir FDE，用 paip 技能栈对陌生业务数据集端到端交付。

## 一、假设与判定

**假设**：给一个陌生业务数据集，AI 用 paip 技能栈（8 skills + 5 引擎）能端到端产出可信交付包（建模+清洗+ER+期望+自评+维护文档），即"技能栈+确定性引擎"可以作为 AI 交付服务的基础设施。

**判定：✅ 假设成立**（带一个硬约束修正，见 §五）。

## 三、对照历史教训（AI-FDE 的核心价值）

| 历史教训（demo-data 审计） | AI-FDE 表现 |
|---|---|
| A1 合并产物主键重复 16/16 | **规避**：ER 以声明交付（不物化缺陷合并），物化产物主键唯一 0 重复 |
| A2 引用外键 0/2604 失配 | **根治**：零改键（清洗只动值不动键），引用命中 3000/3000 + 2000/2000 = 100% |
| A4 ER 覆盖率 8% | **根治**：确定性 email 全量配对 160/160 = 100% |
| B6 负数量信号被抹除 | **根治**：cast 保留负号 + 期望固化，负数量 168 行保留 |
| P14 日期月日颠倒 | **规避**：MM/DD 与 DD-MM 分两条规则 + 语义标注 + 期望残留=0 |

**关键洞察**：AI-FDE 不仅复刻了 Palantir 机制，还主动预判了 paip 引擎的已知缺陷（A1 追加式合并语义、A2 改键破坏引用），选择"声明级 ER + 零改键"策略绕开——说明**技能栈中的教训沉淀（engineering-principles / skill 铁律）能约束 AI 行为**，这正是"技能栈作为 AI 交付基础设施"的证据。

## 四、过程中发现的问题（实验价值）

1. **links.json cardinality 语义错误**：AI 写 `N:1`，引擎只接受 `1:1/1:N/N:M`（source→target 视角）→ 宿主修复为 `1:N`。说明静态编写产物必须经引擎 validate 兜底（流程本身工作正常）。
2. **verify.js 主键口径缺陷**：初版遍历全部中间产物（exec 全表快照语义导致跨产物重复计数）→ 修正为仅查最终 cast 产物（24/24）。属评估工具问题，非交付缺陷。
3. **AI-FDE 无命令执行通道**（最大限制）：子代理无法运行引擎命令，全部产物静态编写 + 静态推演，验证依赖宿主代跑。**教训：AI-FDE 生产形态必须配套命令执行通道（MCP/bash），否则"验证链"断裂**——这正好印证深度分析四维模型中"执行能力是硬前提"。

## 五、结论与建议

1. **假设成立（有约束）**：AI 能按技能栈对陌生数据完成端到端交付，且质量显著优于历史 demo（覆盖率 8%→100%、引用 0%→100%、信号保留、缺陷主动规避）。约束：需要命令执行通道，且引擎缺陷（v2.2 合并语义）修复后 ER 可升级为物化级。
2. **方向 C 值得继续**：下一步把 AI-FDE 从"实验子代理"升级为"可复用服务"：
   - 给 AI-FDE 提供 bash/引擎执行通道（本轮最大痛点）；
   - 将本实验的 ground-truth + eval.js + verify.js 沉淀为 paip 正式资产（tests/ 或 demo-data/verify/ 同级）；
   - 引擎 v2.2 修复合并行语义后重跑，验证 ER 物化级交付。
3. **对生产落地的意义**：本实验证明"软件复现"做不到的事（组织/交付维度），**AI-FDE 服务形态可以部分替代**——AI 即 FDE（建模+清洗+ER+期望+维护文档全包），这正是 Palantir 人力密集模式的 AI 化替代路径的可行性证据。
