# 实验报告：merge-semantics

## 结论
H3a/H3b/H3c/H3d **全部成立**（键映射替换、左表优先、fan-out 防护、实例级合并均可实现）；探索性用例暴露 **2 处 spec 未定义行为**（无重叠键、右表独有键行）。

## 结果数据
| 用例 | 预期 | 实际 | 判定 |
|---|---|---|---|
| 正常合并（左 4 右 3，2 键重叠） | 主键替换 + `vip` 补齐；mapping 2 对 | 一致 | ✓ |
| 同名列冲突 | 左值保留 `Alpha`，右值 `name_right: ALPHA-v2` | 一致 | ✓ |
| fan-out（右表键重复） | 中止、无产物 | `ok:false, reason:"键不唯一: left=null right=k1"` | ✓ |
| fan-out（左表键重复） | 中止、无产物 | `ok:false, reason:"键不唯一: left=k1 right=null"` | ✓ |
| 无重叠键（探索性） | spec 未定义 | `merged`=左表原样；`mapping`=[]；`rightOnly`=[b1]；列头出现空 `v_right` 冲突列 | 记录 |

## 与假设对照
- H3a（键映射替换 + 补齐）：normal-merge 全字段一致 → **成立**
- H3b（左表优先 + `_right` 后缀）：同名列冲突用例一致 → **成立**
- H3c（fan-out 防护）：双向重复键均中止、无产物 → **成立**
- H3d（实例级）：实现仅操作数据行（无类型级 schema 参与）→ **成立**

## 对设计的影响
- §3.1/§4 合并语义确认可实现，实现复杂度低（dict 操作 + 唯一性预检）
- **spec 需补充 2 处语义**（实验暴露）：
  1. **无重叠键**：合并表 = 左表原样、mapping 空——但列头会出现右表同名列的 `_right` 空列（列结构声明与行值不一致）。建议：无重叠时合并表列头不声明右表列（只有实际并入的右表列才进列头），或明确"空列保留"。
  2. **右表独有键行**：当前实现不并入合并表（仅记录 rightOnly）——数据会静默丢失。建议 spec 明确：右表独有键行丢弃（mapping 表可查）或产出 rightOnly 报告，二选一写入 §4。
- mapping 表结构确认：`[{right, left}]` 数组，`<merge-id>-mapping.csv` 形态可行

## 局限与后续
- 未测：3+ 源传递链（spec 明确不在本次范围）
- 未测：右表为空、键列本身在同名列集合中（键列冲突处理：实验跳过右表键列，隐含"主键用左表"）
- fan-out 的"warning 级别错误"（spec 说报 warning）与"中止"并存——实验采用中止（无产物），spec §4 表述建议统一为中止
