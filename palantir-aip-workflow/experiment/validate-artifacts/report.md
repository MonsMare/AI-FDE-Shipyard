# 实验报告：validate-artifacts

## 结论
H1 **成立**：产物格式校验器（validate.js 核心逻辑）可用现有 approved/ 结构直接实现，合法产物 0 问题、非法产物完整列出问题。额外发现"一条记录可触发多条校验"的合理行为。

## 结果数据
| 用例 | 期望问题数 | 实际问题数 | 说明 |
|---|---|---|---|
| 合法产物（对象有主键/链接存在/type合法/confidence 0-1） | 0 | 0 | ✓ |
| 非法产物（缺主键/链接指向Ghost/cardinality 1:X/type magic/confidence 1.5） | 4 | 5 | L2 同时违反"对象不存在"+"cardinality 非法"两条 |

## 与假设对照
- H1（现有结构可直接实现校验）：数据 → **成立**。全部 4 类校验规则（对象主键/链接存在性+cardinality/转换 type/合并 confidence）都正常工作。
- 附加发现：一条记录可触发多条问题（L2 两条）——符合"全部列出后再退出"的错误处理设计，无需修正。

## 对设计的影响
- validate.js 的结构确认：按 4 类产物各一组校验函数，聚合返回问题列表（不中断）。与 spec 第 5 节"全部列出后退出"一致。
- 细节补充：链接校验的"对象存在"应检查**已批准对象**（approved）还是**staging 全量**？本实验用 approved。设计需明确：validate 对 approved 用 approved 集合，对 --stage 用 staging 集合（含 approved 作为基准）。
- 细节补充：对象缺主键与链接指向该对象会同时报两条——可接受（问题全列出）。
