# paip v2.1 迭代计划（缺陷修复 + 设计完善 + evals-lite）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按能力测试报告（P1-P14）与 Palantir 对比分析报告的建议，修复 paip 的高严重度缺陷、统一 skill 口径、补全规则效果评估（evals-lite）与 schema 推断质量，形成 v2.1。

**Architecture:** 引擎层（validate/exec/audit/csv/schema-infer + 新增 bin/eval.js）→ skill 层（8 个 SKILL.md 口径统一）→ 模板层（templates/ontology-project 同步）→ 数据层（demo-data 规则闭环）。每任务独立可测（node --test）。

**Tech Stack:** Node 24（零依赖）、node:test、现有 bin/ 模式（CommonJS + module.exports）。

## Global Constraints

- 零第三方依赖（沿用）
- 规则权威枚举为 **10 种**：regex_replace / regex_extract / map / filter / concat / split / cast / lower / upper / trim（修正规则数笔误）
- 状态机 7 步：init → source → infer → model → entity → review → exec（模板与 skill 必须一致）
- 铁律：失败中止、数据不动、状态不推进；零副作用
- 错误格式：`✘ [id] 原因`，全部列出
- 迭代边界：LLM 节点 / OAG-lite / 动作语义 / ER 增强 / 引擎适配层 / 模型可替换 → **v2.2+**（本次不做，仅文档标注）

- [ ] **Step 3: 实现**：execProject 中 `wantedT` 存在时 `ms = []`（transform 模式跳过 merge）；`wantedM` 存在时 `ts = []`；两者都存在时各自过滤：

```js
const wantedT = opts.transformIds ? new Set(opts.transformIds) : null;
const wantedM = opts.mergeIds ? new Set(opts.mergeIds) : null;
const onlyT = wantedT && !wantedM;
const onlyM = wantedM && !wantedT;
const ts = wantedT ? transforms.filter((t) => wantedT.has(t.id)) : (onlyM ? [] : transforms);
const ms = wantedM ? merges.filter((m) => wantedM.has(m.id)) : (onlyT ? [] : merges);
```
